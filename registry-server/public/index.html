END-TO-END WORKFLOW

How Murmur & The Registry Work Together

The registry is only a matchmaker for finding peer addresses. It never touches your chat data.

01
LOCAL BOOT

Node Init & STUN Punch

Your Rust CLI app boots up, generates an Ed25519 keypair, binds local UDP port 8080, and contacts STUN servers to discover its public IP & NAT mapping.

$ murmur run --handle @alice
02
MATCHMAKING

Global Handle Registry

The node sends a one-time POST /api/register to murmur.debyte.space. Upstash Redis verifies handle uniqueness and records your active QUIC endpoint.

SET murmur:user:alice → 200 OK
03
PEER DISCOVERY

Query Peer Address

When Alice types /connect @bob, her Rust client calls GET /api/lookup?username=bob. The registry returns Bob’s public IP, port, and Ed25519 public key.

GET /api/lookup?username=bob
04
100% P2P MESH

Direct Encrypted QUIC

Alice and Bob punch NAT holes and open a direct TLS 1.3 / QUIC tunnel. All messages, keystrokes, and files flow strictly peer-to-peer. Even if the server goes offline, your chat continues!

Alice ⇔ [Direct QUIC Tunnel] ⇔ Bob
